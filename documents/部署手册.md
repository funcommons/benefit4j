# benefit4j 部署手册

> **版本** v1.2.6 · **更新** 2026-08-22 · **状态** 已发布 · **维护** benefit4j 团队
> 以代码现状为准。framework4j v1.2.6 · Spring Boot 3.2.7 · 前端 Vue 3.5。
> 模式设计参考 `backend/双模式技术方案.md`（user-starter 模式，benefit4j 镜像同一模式）。

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 17 | 后端 + 前端构建 |
| Maven | 3.8+ | 后端构建 |
| PostgreSQL | 16+ | `?stringtype=unspecified` 参数必需（JSONB update cast 治本） |
| Redis | 6+ | framework4j cache/idempotency/signature/rate-limit/nonce |
| Node | 20+ | 前端构建 |
| Docker | 24+ | 可选，PG/Redis 容器化 |

## 2. 部署形态选型

benefit4j 一份 jar，通过 `application.yml` 两开关适配三场景：

| 形态 | `benefit4j.{域}.mode` | `enable-api` | 适用 |
|---|---|---|---|
| **A. 独立部署** | `local` | `true` | 中台独立起 HTTP，对外暴露 OpenAPI（异构客户端 Python/Go 可调）+ 前端管理后台 |
| **B. 单体嵌入** | `local`（默认） | `false` | 业务方单体引 `benefit4j-starter`，`@Autowired Client` 同进程 Java 调用，零 HTTP |
| **C. 跨进程调用** | `remote` | — | 业务方同 Client 接口，框架自动走 HttpTransport 调远端 benefit4j |

4 个 Client 接口（业务方唯一注入点）：`BenefitRuntimeClient` / `BenefitTenantClient` / `BenefitPlatformClient` / `BenefitOpsClient`。

## 3. 形态 A：独立部署（中台自起 HTTP）

### 3.1 数据库初始化

benefit4j-app **未启用 Flyway**，需手动建表：

```bash
# PG 已建库 benefit4j
psql -h <pg_host> -U admin -d benefit4j -f backend/schema.sql
# 15 张表（11 ubma_* + 3 ubmp_benefit_tmpl_* + 1 ubmp_audit_log）
# 可选 seed 模板数据
psql -h <pg_host> -U admin -d benefit4j -f backend/benefit4j-app/src/main/resources/db/migration/V1.0.1__seed_tmpl_mock.sql
```

> 迁移脚本目录 `backend/benefit4j-app/src/main/resources/db/migration/`（V1.0.0/V1.0.1/V1.2.0/V1.2.1）需手动按序执行，或直接用 `schema.sql`（已含 V1.2.0/V1.2.1 全量）。

### 3.2 后端打包 + 启动

```bash
cd backend
mvn -pl benefit4j-app -am package -DskipTests
java -jar benefit4j-app/target/benefit4j-app-1.0.0-SNAPSHOT.jar
# 默认监听 9200
```

### 3.3 环境变量（生产必改，勿用默认）

| 变量 | 默认值（不安全） | 生产取值 |
|---|---|---|
| `JWT_SECRET` | `changeme_super_secret_key_32_chars_long` | 随机 ≥32 字符 |
| `HASH_SALT` | `salt` | 随机盐 |
| `AES_KEY` | `12345678901234567890123456789012` | 从 KMS 取，≥32 字符（app_secret 加密） |
| `PLATFORM_CLIENT_ID` | `PLATFORM` | 平台运维账号 ID |
| `PLATFORM_CLIENT_SECRET` | `fvUQ54yPgrMg2v2X` | 随机强密码 |
| `PG_HOST/USER/PASSWORD` | — | PG 连接 |
| `REDIS_HOST` | `localhost` | Redis 地址 |

```bash
export JWT_SECRET=$(openssl rand -hex 32)
export AES_KEY=$(openssl rand -hex 32)
export HASH_SALT=$(openssl rand -hex 16)
export PLATFORM_CLIENT_SECRET=$(openssl rand -hex 16)
java -jar benefit4j-app-*.jar
```

### 3.4 前端构建 + Nginx

```bash
cd frontend
npm ci
npm run build          # vue-tsc -b && vite build → dist/
```

Nginx 配置（静态 + API 反代到 9200）：
```nginx
server {
  listen 80;
  server_name benefit.example.com;
  root /opt/benefit4j/frontend/dist;
  location / { try_files $uri /index.html; }       # SPA
  location /benefit/api/ { proxy_pass http://127.0.0.1:9200; }  # 后端
}
```

> 注：`frontend/vite.config.ts` 的 dev proxy `/api` target 默认 8080，开发联调需改成 `http://localhost:9200`；生产走 Nginx 不用 dev proxy。

### 3.5 验证

```bash
# 健康探针
curl http://localhost:9200/benefit/api/v1/ops/health
# 平台登录拿 token
curl -X POST http://localhost:9200/benefit/api/v1/auth/token \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d "client_id=$PLATFORM_CLIENT_ID&client_secret=$PLATFORM_CLIENT_SECRET&grant_type=client_credentials"
```

## 4. 形态 B：单体嵌入（业务方同进程）

业务方单体引入 starter，权益逻辑跑在业务方进程内，**零独立部署**。

### 4.1 引依赖

```xml
<dependency>
  <groupId>fun.commons.benefit4j</groupId>
  <artifactId>benefit4j-starter</artifactId>
  <version>1.0.0-SNAPSHOT</version>
</dependency>
<!-- framework4j v1.2.6 由 starter 传递引入 -->
```

### 4.2 业务方 yml

```yaml
benefit4j:
  runtime:
    mode: local          # 同进程（默认）
    enable-api: false    # 不暴露 Controller，纯同进程
  tenant:
    mode: local
    enable-api: false
  # platform/ops 按需（业务方一般不需要平台管理）
framework4j:
  datasource:
    enabled: true
    datasources:
      default:
        url: jdbc:postgresql://<pg>:5432/benefit4j?stringtype=unspecified
        username: ...
        password: ...
        mybatisPlusPlugins: { optimisticLock: true, pagination: true, blockAttack: true, dbType: POSTGRE_SQL }
  redis:
    enabled: true
    datasources:
      default: { host: <redis>, port: 6379 }
  access-token:
    enabled: true
    redis-name: default
    secret-key: ${JWT_SECRET}
    hash-salt: ${HASH_SALT}
  sensitive:
    enabled: true
    encryption-key: ${AES_KEY}
  # idempotency/audit/signature/rate-limit/sql-tracing 按需开
```

### 4.3 业务方建表

业务方 PG 执行 `schema.sql`（可独立 schema 或专用库）。

### 4.4 业务方调用

```java
@Autowired BenefitRuntimeClient runtimeClient;

public void 充值后扣减(Long appId, String userid) {
    var req = new PostConsumesDirectRequest();
    req.setUserid(userid);
    req.setItemId("xxx");
    req.setConsumeNum(10);
    req.setExternalOrderId("order-001");
    runtimeClient.postConsumesDirect(appId, req);   // → LocalBenefitRuntimeClient → service 直接执行
}
```

业务方只感知 Client 接口，不感知 local/remote。后续若拆服务，改 yml `mode=remote` 即可，业务代码零改动。

## 5. 形态 C：跨进程（业务方调远端 benefit4j）

中台独立部署（形态 A）后，业务方不引 starter，走 HTTP：

```yaml
benefit4j:
  runtime:
    mode: remote
    remote-url: http://benefit4j.internal:9200   # 远端中台地址
  tenant:
    mode: remote
    remote-url: http://benefit4j.internal:9200
```

业务方仍 `@Autowired BenefitRuntimeClient`，框架自动用 HttpTransport 调远端。runtime 域需带签名头（见 §7）。

## 6. framework4j 能力开关（application.yml）

| 模块 | 配置 prefix | 默认 | 生产建议 |
|---|---|---|---|
| AccessToken | `framework4j.access-token` | enabled | 开，JWT + Redis nonce 单会话 |
| 接口签名 | `framework4j.signature` | enabled:false | runtime 对外时开 true + path-patterns |
| 限流 | `framework4j.rate-limit` | 无 | 开，scope=APP，消费 50/分 查询 300/分 |
| 幂等 | `framework4j.idempotency` | enabled:true | 配 path-patterns 指向资金写操作 |
| 审计 | `framework4j.audit` | enabled:true | 开，table=ubmp_audit_log |
| 字段加密 | `framework4j.sensitive` | enabled:true | 开，AES_KEY 从 KMS |
| SQL 追踪 | `framework4j.datasource.sql-tracing` | matchIfMissing=true | 显式配 mode=ALL |
| 多数据源 | `framework4j.datasource` | — | 配 PG |
| 多 Redis | `framework4j.redis` | — | 配 Redis |

## 7. runtime 域安全接入（三方 App 调用）

runtime 域强制 `@RequiresToken(APP)` + `@RequiresSignature` + `@RateLimit` + 幂等。三方需：

1. **登录换 token**：`POST /auth/token`（client_credentials，client_id=app OpenID，client_secret）
2. **每次请求带 4 个签名头**：
   - `X-Access-Key`：app_id（OpenID 字符串）
   - `X-Timestamp`：Unix 毫秒（±5min 容忍）
   - `X-Nonce`：UUID v4（10min 防重放）
   - `X-Signature`：`base64(HMAC_SHA256(app_secret, 签名串))`
3. **签名串**（framework4j `SignatureUtil`）：
   ```
   METHOD\nPATH\nTIMESTAMP\nNONCE\nBODY_MD5_HEX
   ```
   - PATH：不含 query
   - BODY_MD5_HEX：空 body = `md5("")` = `d41d8cd98f00b204e9800998ecf8427e`
4. **资金写操作带 `Idempotency-Key`**（UUID v4）：重复提交返回 409 并回放首次响应

示例（Python）：
```python
import hmac, hashlib, base64, time, uuid
sts = f"GET\n{path}\n{ts}\n{nonce}\n{body_md5}"
sig = base64.b64encode(hmac.new(secret.encode(), sts.encode(), hashlib.sha256).digest()).decode()
```

## 8. 运维接口（OPS 域，`@RequiresToken(OPS)`）

| 接口 | 用途 |
|---|---|
| `GET /ops/health` | DB/Redis 健康探针 |
| `GET /ops/metrics` | Prometheus 指标 |
| `POST /ops/cache/evict` | 紧急缓存淘汰 |
| `POST /ops/jobs/refresh-cycles` | 周期结转（刷新订阅周期 + 标 EXPIRED + 统计 `expired_bucket_count`） |
| `POST /ops/migrate/encrypt-app-secret` | **一次性**：app_secret 全量加密迁移（`benefit4j.migration.app-secret-encrypt=true` 开关，跑完关） |

## 9. app_secret 加密迁移（上线关键步骤）

benefit4j 的 `app_secret` 走 AES-256-GCM 加密存储。若 DB 有历史明文：

```bash
# 1. 临时开迁移开关（yml 或 env）
export BENEFIT4J_MIGRATION_APP_SECRET_ENCRYPT=true  # 或 yml: benefit4j.migration.app-secret-encrypt: true
# 2. 重启
# 3. 调一次性接口
curl -X POST http://localhost:9200/benefit/api/v1/ops/migrate/encrypt-app-secret \
  -H "Authorization: Bearer $OPS_TOKEN"
# 返回: {"total":N,"migrated":X,"skipped_already_encrypted":Y,"failed":Z}
# 4. 关开关，重启
```
