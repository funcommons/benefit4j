# ADR-0008: 新建 assets 域独立于权益桶 + 独立于钱包中台

> **状态**: 已决定 · **日期**: 2026-08 · **版本**: v0.4 · **关联**: [assets-design.md §12](../assets-design.md)

> v0.4 增补(第二轮评审):幂等闸外移至独立 `ubmx_tx_order` 表(O10,分区表唯一键含分区键会稀释幂等);边界户(`world:*`/`issue:*` 等)`account_type='BOUNDARY'` 豁免行锁与余额更新(O11,根治单行热点);锁策略定案行锁为主、version 仅审计(O12);**F1 授信负余额定为正式能力**——P1 落 `credit_limit`/`can_credit` 列(默认 0 行为不变),P2 实现完整授信(OPS 调额双签/还款分录/负余额禁提现);**F2-F5 均不做**——域定位定案:assets = 非周期性资产(周期权益归权益域 `refresh_cycle`,计费编排归计费方,资金渠道归钱包中台),**资产定义为「元」(CNY)时即为简单钱包,直接支撑按量计费**。

## 背景

余额型场景(钱包/储值卡/多资产钱包/支付与账务)与现有权益中台模型在四个维度上语义偏差:

| 维度 | 配额型(权益中台现有) | 资产型(本期) |
|---|---|---|
| 精度 | 整数(`Integer`) | 小数(`NUMERIC(20,4)`) |
| 资源 | 桶 = 订阅明细,依附订阅生命周期 | 账户 = (主体 × 资产),独立,长期存在 |
| 资产种类 | 单次只能销同一权益项 | **多资产组合**支付(积分抵5 + CNY 23 + 费2) |
| 会计视图 | 桶内 `periodConsumed` 累计 | **复式分录**流水,资产恒等式 |
| 监管 | 不碰资金,合规风险极低 | **资金自持**(若启用 FIAT)触及二清 |

同时,钱包/储值的**真实资金渠道接入**(充值/提现/原路退)不应与账本耦合——账本是账,渠道是渠道,两者责任域不同。

## 决策

1. **新建 `assets` 域**(6 张表 `ubmx_asset/account/posting/tx_order/pre_consume` + 冻结原因表 `ubmx_freeze`),不复用 `ubma_subscribe_item`
2. **资产域只承担账本能力**;真实法币渠道接入(充值/提现/原路退)由未来独立的「钱包中台」项目承担
3. **钱包中台对资产域是 EXTERNAL subject**,通过 `POST /assets/runtime/issue` 内部 API 写账本,**钱包中台可独立演进、替换、迁移**

## 理由

### 为什么不复用桶

- 永不过期/不刷新/不与订阅关联全靠业务方自律,资金风险无兜底
- 复式分录语义靠拼接(权益桶三字段拼余额+冻结+累计,语义模糊)
- 桶的 `quotaLimit` 字段语义错位(配额上限 ≠ 余额),容易误导业务方
- DB `CHECK (>= 0)` 等资金安全约束无法在权益桶上施加

### 为什么独立于钱包中台

- 资产域账本与支付渠道是两个生命周期——钱包中台可换,资产域 schema 不变
- 资产域的入账接口(`issue`)只暴露给钱包中台/运营端,**业务系统不直接感知钱怎么进来**
- 钱包中台独立演进:支持更多渠道(KJePay/银联/支付宝/微信)、提现两段式、原路退等,**资产域一行不动**
- 钱包中台本身可能是另一个 `owner_type=EXTERNAL` 的账户,资产域对其记账但不知其内部状态

### 为什么冻结分桶(`ubmx_freeze`)

- 单一 `frozen` 字段无���区分"提现冻结"vs"售后冻结"vs"风控冻结"
- 大厂(Stripe/PayPal)冻结按原因分桶,审计与释放更精细
- 明细表多 5% 性能开销换审计可追溯——值得

## 后果

### ✅ 正面

- 资金安全 schema 兜底:`CHECK (>= 0)` + append-only posting + CAS 乐观锁
- 多资产组合支付多腿事务自然
- 资产恒等式可对账校验(`Σbalance = Σissue − Σburn`)
- 钱包中台独立演进,资产域 schema 不变
- 冻结粒度细到原因,可追溯

### ⚠️ 负面

- 复用 `ReserveTimeoutScheduler` 等模式但不复用表(代码复用度可接受)
- MMagiX 迁入需双跑灰度
- 钱包中台独立项目需另立项(本设计不阻塞)
- 冻结双源(`frozen` 字段 + `ubmx_freeze` 表)需对齐一致性(P2 同步实施)

### 📋 后续

- P1:基础账本(5-7 天)
- P2:多资产 + 对账 + 双扣 + 限额 + 冻结分桶(5-7 天)
- 钱包中台独立项目立项(不阻塞资产域)
- MMagiX 灰度迁移(独立项目)
