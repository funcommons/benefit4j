# benefit4j 嵌入接入指南

> **版本** v1.2.6 · **更新** 2026-08-22 · **状态** 已发布 · **维护** benefit4j 团队
> 以代码现状为准。

## 1. 目标

让**第三方前端**（外部业务方）通过一条 URL 地址即可把权益中台的页面嵌入
自己的界面，既能嵌入**单页**（无 header / aside），也能嵌入**完整 app 页**
（带侧栏）。无需在第三方侧实现登录、品牌皮肤或菜单。
> **认证分两级**：基础级（URL 带 token，简单）和推荐级（postMessage 握手，
> token 不进 URL）。第三方按自身安全要求选择。

---

## 1. 背景与动机

后端 `/benefit/api/v1/auth/token` 已支持 client_credentials 颁发 `access_token`，前端
`useBenefitAuthStore` 已持久化到 `localStorage`，路由守卫也已经按 `isLoggedIn` 拦截。
前端 `FcThemeProvider` + `oem` store 已实现品牌/主题/语言的多源覆盖。

但要"被三方前端嵌入"还存在四块缺口：

1. **缺少 URL 参数入口**：第三方只能先跳到登录页，登录后才能进入；无法在自己域内
   通过 `iframe` / 微前端 / `window.open` 直接携带令牌 + 皮肤落地。
2. **缺少免登录快捷方式**：第三方每次嵌入都得走完整登录；无法用 `?access_token=...`
   一次性免登。
3. **缺少单页模式**：第三方 `iframe` 嵌入时不需要侧栏菜单，目前 `BenefitLayout.vue`
   始终渲染 `FcSidebar`。
4. **跨域边界不明**：第三方域 vs benefit4j 域，localStorage / cookie 互不共享，
   token 必须可由 URL 携带；后端 CORS / X-Frame-Options 策略需要被本方案显式假定。

本方案在已有 `/app/*` 路由旁增加 `/page/*` 平行路由，配合 query 参数
(`brand` / `mode` / `language`)，让三方前端只需要拼一条 URL 即可嵌入。
认证走两级安全方案（§8），由第三方自选。

## 2. 入口与参数规范

### 2.1 两种入口模式（由路由前缀决定）

| 模式 | 路由前缀 | 用途 |
|---|---|---|
| **完整 app 嵌入** | `/benefit/platform/app/*` / `/benefit/tenant/app/*` | 三方前端希望保留侧栏，便于用户在被嵌入的视图里继续跳转其他页面（适合深度操作）。 |
| **单页嵌入** | `/benefit/platform/page/*` / `/benefit/tenant/page/*` | 三方前端只展示某一个具体业务页面，**不带 header / aside**（适合 iframe 嵌一个看板 / 列表）。 |

`/page/*` 与 `/app/*` 共用同一组 View 组件 (`PlatformItems.vue` / `Sets.vue` / ...)，
仅外层 layout 不同 — 共享逻辑、零组件复制。

### 2.2 query 参数（两种入口模式通用）

| 参数 | 类型 | 必填 | 作用 |
|---|---|---|---|
| `brand` | enum | 否 | **色调**。值域沿用现有品牌 id：`ldx2` / `apple` / `google` / `mchuan` / `manyun` / `acme` / `microsoft` / `vonnex`。缺省走 OEM → localStorage → 默认 `ldx2`。 |
| `mode` | `light` / `dark` | 否 | **明暗**。值合法时写入 `data-theme` 属性，对应 `_themes.scss` 的 `$themes` map。缺省走 OEM → localStorage → 默认 `light`。 |
| `language` | `zh-CN` / `en-US` | 否 | 强制 locale。缺省走 OEM → localStorage → 默认 `zh-CN`。 |

> **`access_token` 不再是 query 参数**（推荐级）。基础级仍支持 `?access_token=...`，
> 见 §8.1。推荐级走 postMessage 握手，token 不出现在 URL 中，见 §8.2。

#### URL 示例

```
# 推荐级 — URL 不含 token, iframe 加载后由 postMessage 握手获取
https://benefit.example.com/benefit/tenant/page/dashboard
  ?brand=acme&mode=dark&language=zh-CN

# 基础级 — URL 带 token (简单场景)
https://benefit.example.com/benefit/tenant/page/dashboard
  ?access_token=eyJhbGciOi...
  &brand=acme&mode=dark&language=zh-CN

# 同源用户直接访问（不带任何嵌入参数）
https://benefit.example.com/benefit/tenant/page/dashboard
```

### 2.3 优先级（叠加规则）

> **query > postMessage > OEM（按 host） > localStorage 持久化 > 内置默认**

- **认证**：推荐级走 postMessage（§8.2）；基础级走 URL query `access_token`（§8.1）。
  两者互斥 — iframe 端检测到 URL 有 `access_token` 时走基础级，否则等待 postMessage。
- `brand` / `mode` / `language`：query 出现时覆盖一切；未出现时走 OEM `getOemConfig()` → 持久化 → 内置默认。
- 持久化策略：query 参数 apply 后**不写入** localStorage，避免污染宿主下次直接访问的体验。OEM / 用户偏好仍照常持久化。

### 2.4 第三方嵌入（跨域）的隐含约束

| 维度 | 行为 | 说明 |
|---|---|---|
| **localStorage** | 跨域隔离 | 三方域与 benefit4j 域不共享 localStorage。推荐级 token 只在 iframe 内存中，不写 localStorage。基础级首次写入 localStorage 供 iframe 内 SPA 跳转复用。 |
| **Cookie** | 同上隔离 | 后端若有 cookie-based session，本方案不依赖；本方案走 header `Authorization: Bearer`。 |
| **CORS** | 需要后端放行 | 后端 `/benefit/api/v1/**` 与 `/api/v1/oem/**` 需要 `Access-Control-Allow-Origin: <三方域>` 与 `Access-Control-Allow-Credentials: false`（token 在 Header，不在 cookie）。 |
| **X-Frame-Options / CSP frame-ancestors** | 需要放行嵌入域 | 后端响应头需允许三方域嵌入（如 `Content-Security-Policy: frame-ancestors <三方域> <localhost>`），否则 iframe 加载会失败。 |
| **Referer 泄漏** | 基础级: token 在 URL → 泄漏风险 | 推荐级无此问题（URL 不含 token）。基础级需 `referrerpolicy="no-referrer"`。 |

## 3. 实现拆解

### 3.1 新建 `useEmbedParams` composable（`src/composables/useEmbedParams.ts`）

职责：解析当前 URL query 中的**外观参数**（brand / mode / language），分发到各 store。
认证参数（access_token）由 `useEmbedToken`（§3.7）处理。

```ts
// 伪代码签名（仅展示职责，不实现细节）
export function useEmbedParams() {
  return {
    /** 从当前 route.query 解析外观参数（一次性） */
    parseFromRoute(route: RouteLocationNormalizedLoaded): EmbedAppearanceParams,
    /** 把外观参数 apply 到 store / DOM；幂等 */
    applyAppearance(params: EmbedAppearanceParams): void,
  }
}

interface EmbedAppearanceParams {
  brand?: Brand
  mode?: 'light' | 'dark'
  language?: 'zh-CN' | 'en-US'
}
```

行为：
- 解析在路由守卫 **beforeEach** 之前完成（main.ts bootstrap 阶段或 App.vue setup）。
- `applyAppearance` 调用现有：
  - `usePreferenceStore().setFromEmbed({ brand, theme: mode, locale: language })`。
  - `oem.apply()` 不需要再处理 `color` 参数（已移除）。

> **持久化策略补丁**：`usePreferenceStore.setBrand/setTheme/setLocale` 当前一律 `persist()`。
> 需要补一个 `embed` 标志位（或新增 `setFromEmbed`），让 query 触发的变更不写
> localStorage；用户主动在 UI 里切换品牌/主题仍然持久化。

### 3.2 路由守卫扩展（`src/router/index.ts`）

现有 `beforeEach` 已经在 `isBenefitRoute` 判断里做了 login 拦截。新增以下逻辑：

```ts
// 1. 嵌入外观参数解析（在 beforeEach 入口位置）
const embed = useEmbedParams()
const params = embed.parseFromRoute(to)
embed.applyAppearance(params)

// 2. 认证: 基础级 — URL 带 access_token
const urlToken = to.query.access_token as string | undefined
if (urlToken) {
  useBenefitAuthStore().setToken(urlToken, undefined)
}
// 推荐级 — 认证由 useEmbedToken (PageLayout 内) 的 postMessage 握手完成,
// 路由守卫不处理; 若握手未完成, 守卫正常跳登录页。
```

同时把 `/page/*` 加入 `isBenefitRoute` 命中范围（沿用同一登录守卫）。

> **不要**新增 `isEmbedRoute` 守卫分支；嵌入模式只是"已登录 + 单页 layout"，
> 不需要额外的权限或菜单策略。`/page/*` 应被视为受保护路由，跟 `/app/*` 行为完全一致。

### 3.3 路由表扩展（`src/router/index.ts`）

新增两组平行路由 — View 组件完全复用，只换 layout：

```ts
{
  path: '/benefit/platform/page',
  component: () => import('@/layout/PageLayout.vue'),  // 新建, 单页 (无 FcSidebar)
  meta: { benefitAuth: true, layout: 'page' },
  redirect: '/benefit/platform/page/dashboard',
  children: [
    { path: 'dashboard', component: () => import('@/views/benefit/PlatformDashboard.vue'), meta: {...} },
    { path: 'items',     component: () => import('@/views/benefit/PlatformItems.vue'),     meta: {...} },
    { path: 'sets',      component: () => import('@/views/benefit/Sets.vue'),              meta: {...} },
    { path: 'subscriptions', component: () => import('@/views/benefit/Subscriptions.vue'), meta: {...} },
    { path: 'consumptions',  component: () => import('@/views/benefit/Consumptions.vue'),  meta: {...} },
  ],
},
{
  path: '/benefit/tenant/page',
  component: () => import('@/layout/PageLayout.vue'),
  meta: { benefitAuth: true, layout: 'page' },
  redirect: '/benefit/tenant/page/dashboard',
  children: [
    { path: 'dashboard', component: () => import('@/views/benefit/TenantDashboard.vue'), meta: {...} },
    { path: 'items',     component: () => import('@/views/benefit/Items.vue'),            meta: {...} },
    { path: 'sets',      component: () => import('@/views/benefit/Sets.vue'),             meta: {...} },
    { path: 'subscriptions', component: () => import('@/views/benefit/Subscriptions.vue'), meta: {...} },
    { path: 'consumptions',  component: () => import('@/views/benefit/Consumptions.vue'),  meta: {...} },

```

要点：
- `path` 一律使用 `meta.title` + `meta.icon` 的现有 key，菜单名称复用，不另起 i18n key。
- `meta.layout = 'page'` 用于 `PageLayout.vue` 自身的判断与文档（可选）。
- 路由级 `meta.benefitAuth: true` 沿用现有守卫行为：未登录仍跳登录页。

### 3.4 新建 `PageLayout.vue`（`src/layout/PageLayout.vue`）

参照现有 `BenefitLayout.vue`，但**只保留 `<router-view />` 的容器**，不渲染
`FcSidebar` 和任何 header / 面包屑：

```vue
<template>
  <div class="page-layout">
    <div class="page-container">
      <router-view />
    </div>
  </div>
</template>

<script setup lang="ts">
import { useEmbedToken } from '@/composables/useEmbedToken'

// 推荐级: postMessage 握手 (token 不进 URL)
// 基础级: URL 带 access_token 时, 此 composable 静默跳过
const { status } = useEmbedToken()
</script>
```

样式参照 `BenefitLayout.vue` 的 `.page-container`（padding 24px，背景 `--app-bg-page`，内部 `overflow-y: auto`），但外层容器改为 `min-height: 100vh` + `width: 100%`，让 iframe 自适应。

> **保留快捷键**：原 `BenefitLayout` 内的 `Cmd/Ctrl+K` 命令面板在嵌入场景下宿主
> 可能不希望触发。PageLayout 不挂这个快捷键，留给宿主业务系统自己实现。

### 3.5 `usePreferenceStore` 持久化补丁（`src/store/preference.ts`）

需要新增以下签名（不动现有调用）：

```ts
actions: {
  /** Embed query 参数专用: 设置 brand/theme/locale 但不 persist */
  setFromEmbed(overrides: { brand?: Brand; theme?: Theme; locale?: Locale }) {
    if (overrides.brand) this.brand = overrides.brand
    if (overrides.theme) this.theme = overrides.theme
    if (overrides.locale) this.locale = overrides.locale
    this.applyToRoot()  // DOM 立即生效
    // 注意：不调 persist()
  },
}
```

调用方 `useEmbedParams.applyAppearance` 用 `setFromEmbed` 而非 `setBrand/setLocale`，
保证 query 参数不会污染 localStorage（避免宿主 iframe 嵌入一次后污染直接访问时的用户偏好）。

### 3.6 后端契约（仅记录，不修改）

嵌入方案完全在后端 0 改动前提下工作：

- `access_token` 复用现有 `/benefit/api/v1/auth/token` 的颁发方式。
- 跨租户 / 租户视角查询的 RBAC 由后端 controller 已有的 `appId` 注入保证。
- 不需要为嵌入模式新增 token 范围 / 短期 token。

### 3.7 新建 `useEmbedToken` composable（`src/composables/useEmbedToken.ts`）

职责：实现推荐级 postMessage 握手。基础级（URL 带 token）时静默跳过。

```ts
// 伪代码签名
export function useEmbedToken(): {
  /** 'idle' | 'waiting' | 'connected' | 'expired' | 'basic' */
  status: Ref<EmbedTokenStatus>
} {
  // 检测: URL 有 access_token → 基础级, 直接返回 status='basic'
  // 检测: URL 无 access_token 且在 iframe 内 → 推荐级, 启动握手
  // 检测: URL 无 access_token 且不在 iframe 内 → 正常用户, status='idle'
}
```

握手协议详见 §8.2。

### 6.2 浏览器端到端

启动 dev server 后，在 `http://localhost:5173/` 执行：

   - 不跳登录页，直接进入租户 dashboard。
   - 刷新页面后仍保持登录（localStorage 持久化）。
3. **推荐级嵌入**：`/benefit/tenant/page/dashboard?brand=acme&mode=dark`（不带 token）
   - 页面加载后进入 `waiting` 状态（等待 postMessage）。
   - 在 DevTools console 模拟父页发送：
     ```js
     // 模拟父页 (需在 iframe 上下文执行)
     window.postMessage({ type: 'TOKEN', access_token: '<token>', expires_in: 3600 }, '*')
     ```
   - 收到后进入 `connected` 状态，API 请求带 Authorization header。
4. **嵌入品牌 + 明暗**：`/benefit/tenant/page/sets?brand=apple&mode=dark`
   - `<html data-brand="apple">` 立即生效。
   - `<html data-theme="dark">` 立即生效。
   - 浏览器侧栏依旧不可见（page 路由）。
5. **嵌入语言**：`/benefit/platform/page/dashboard?language=en-US`
   - i18n locale 立即切到 `en-US`，菜单文案翻成英文。
6. **持久化隔离**：走一遍 `?brand=apple`，然后直接访问 `/benefit/tenant/app/dashboard`
   （不带任何 query），期望仍然使用 localStorage 中原来的 `ldx2`，**不**被 `apple` 污染。
7. **守卫回归**：未带 `access_token` 且无 postMessage 访问 `/benefit/tenant/page/dashboard`
   → 跳 `/benefit/app/tenant/login`。

### 6.3 iframe 嵌入验证

#### 基础级（URL 带 token）

```html
<iframe
  referrerpolicy="no-referrer"
  src="https://benefit.example.com/benefit/tenant/page/dashboard
       ?access_token=eyJ...
       &brand=acme&mode=light&language=zh-CN"
  style="width:100%;height:800px;border:0"
></iframe>
```

#### 推荐级（postMessage 握手）

```html
<iframe
  id="benefit-embed"
  src="https://benefit.example.com/benefit/tenant/page/dashboard
       ?brand=acme&mode=dark&language=zh-CN"
  style="width:100%;height:800px;border:0"
></iframe>

<script>
const iframe = document.getElementById('benefit-embed')
const BENEFIT_ORIGIN = 'https://benefit.example.com'

window.addEventListener('message', async (e) => {
  if (e.origin !== BENEFIT_ORIGIN) return
  if (e.data?.type === 'READY' || e.data?.type === 'RENEW') {
    const { access_token, expires_in } = await fetch('/api/embed/benefit-token', {
      method: 'POST', credentials: 'include',
    }).then(r => r.json())
    iframe.contentWindow.postMessage(
      { type: 'TOKEN', access_token, expires_in },
      BENEFIT_ORIGIN,
    )
  }
})
</script>
```

验证点：
- iframe 内部不出现侧栏。
- iframe 内部不触发 `Cmd/Ctrl+K` 面板。
- 推荐级：iframe URL 不含 token（检查 DevTools Network / 浏览器历史）。
- 推荐级：token 不在 localStorage（检查 DevTools Application → Local Storage）。
- 基础级：iframe 加 `referrerpolicy="no-referrer"` 后，CDN 请求 Referer 不含 token。

## 7. 不做的事（划界）

- **不**修改任何 SDK 文件（`frontend/src/components/sdk/`）。
- **不**修改 `frontend/src/views/dev/`。

  问题（已经通过 `setFromEmbed` 的「不持久化」约束解决）。

## 8. 安全方案选型

第三方前端根据自身安全要求选择认证等级。**两种等级由第三方选，benefit4j 侧
同时支持，无需改代码切换**。

### 8.0 选型速查

| | 基础级（§8.1） | 推荐级（§8.2） |
|---|---|---|
| **token 传递** | URL query `?access_token=...` | postMessage 握手（内存） |
| **token 暴露面** | 7 个（URL / 日志 / Referer / 历史 / 书签 / 代理 / 扩展） | 1 个（iframe 内存） |
| **token 持久化** | 写 localStorage（iframe 内 SPA 跳转复用） | 不写 localStorage（关 tab 即销毁） |
| **跨 origin 滥用防护** | ❌ 无（拿到 token 即可用） | ⚠️ 部分（token 不在 URL，但无签名绑定） |
| **三方集成复杂度** | 最低（拼 URL 即可） | 中（双方各 ~30 行 JS） |
| **适用场景** | 内网 / 低敏 / 快速验证 | 公网 / 高敏 / 生产环境 |
| **等保对应** | 二级 | 三级（配合审计 + 限流 + 加密） |

### 8.1 基础级：URL 带 token

**原理**：三方后端拿 token → 拼进 iframe URL → benefit4j 前端从 URL 解析 → 写
localStorage → 后续 API 请求带 Authorization header。

**三方侧代码**：

```ts
// 三方后端: 拿短期 token
async function buildEmbedUrl(path: string): Promise<string> {
  const { access_token, expires_in } = await fetch('/api/embed/benefit-token', {
    method: 'POST',
  }).then(r => r.json())

  const u = new URL(`https://benefit.example.com${path}`)
  u.searchParams.set('access_token', access_token)
  u.searchParams.set('brand', 'acme')
  return u.toString()
}
```

```html
<!-- 三方前端: iframe -->
<iframe
  referrerpolicy="no-referrer"
  style="width:100%;height:780px;border:0;border-radius:8px"
  :src="embedUrl"
></iframe>
```

**benefit4j 侧处理**（路由守卫，§3.2）：

```ts
const urlToken = to.query.access_token as string | undefined
if (urlToken) {
  useBenefitAuthStore().setToken(urlToken, undefined)
}
```

**风险与缓解**：

| 风险 | 缓解 |
|---|---|
| token 进 access log | token TTL ≤ 1h；nginx `access_log` 过滤 `access_token=` |
| Referer 泄漏 | iframe 加 `referrerpolicy="no-referrer"` |
| 浏览器历史 / 书签 | 无法缓解 — 接受或升级推荐级 |
| 错误监控采集 URL | Sentry `beforeSend` 过滤 query 参数 |
| 跨 origin 滥用 | 无法缓解 — 接受或升级推荐级 |

### 8.2 推荐级：postMessage 握手（token 不进 URL）

**原理**：iframe URL 不含 token。iframe 加载后向父页发 `READY` 消息，父页向
自己后端拿短期 token，再通过 `postMessage` 发给 iframe。token 全程在内存中，
不落 URL、不落 localStorage、不走网络（postMessage 是浏览器内核 IPC）。

**握手时序**：

```
  父页 (3rd.com)                    iframe (benefit.example.com)
      │                                    │
      │  1. <iframe src="...?brand=acme">  │
      │ ──────────────────────────────────→ │
      │     (URL 不含 token)                │
      │                                    │
      │                                    │  2. PageLayout.vue onMounted
      │                                    │     useEmbedToken() 启动
      │                                    │
      │  3. postMessage({type:'READY'})    │
      │ ←────────────────────────────────── │
      │     targetOrigin: 'https://3rd.com'│
      │                                    │
      │  4. 父页收到 READY                  │
      │     校验 event.origin ===          │
      │       'https://benefit.example.com'│
      │                                    │
      │  5. 父页向自己后端拿短期 token       │
      │     POST /api/embed/benefit-token  │
      │     ← { access_token, expires_in } │
      │                                    │
      │  6. postMessage({                  │
      │       type: 'TOKEN',              │
      │       access_token: 'eyJ...',     │
      │       expires_in: 3600            │
      │     })                            │
      │ ──────────────────────────────────→ │
      │     targetOrigin:                  │
      │       'https://benefit.example.com'│
      │                                    │
      │                                    │  7. iframe 收到 TOKEN
      │                                    │     校验 event.origin
      │                                    │     存内存变量
      │                                    │     后续 API 带 Authorization
      │                                    │
      │  8. 定时续签 (每 50min)             │
      │     postMessage({type:'RENEW'})   │
      │ ←────────────────────────────────── │
      │     → 重复 5-6                     │
```

**iframe 端代码**（`useEmbedToken.ts`）：

```ts
import { ref, onMounted, onUnmounted } from 'vue'
import { useBenefitAuthStore } from '@/store/benefitAuth'

export type EmbedTokenStatus = 'idle' | 'waiting' | 'connected' | 'expired' | 'basic'

// 父页 origin 白名单 — 由构建时注入或运行时从 OEM 配置读取
const ALLOWED_PARENT_ORIGINS = ['https://3rd-a.com', 'https://3rd-b.com']

export function useEmbedToken() {
  const status = ref<EmbedTokenStatus>('idle')
  const auth = useBenefitAuthStore()
  let timer: ReturnType<typeof setInterval> | null = null
  let expiresAt = 0

  // 内存变量, 不进 localStorage
  let accessToken: string | null = null

  const isInIframe = () => window.self !== window.top

  const handleMessage = (e: MessageEvent) => {
    // ① Origin 校验 — 浏览器内核设置, JS 不可伪造
    if (!ALLOWED_PARENT_ORIGINS.includes(e.origin)) return

    // ② 消息类型校验
    if (e.data?.type === 'TOKEN' && typeof e.data.access_token === 'string') {
      accessToken = e.data.access_token
      expiresAt = Date.now() + (e.data.expires_in ?? 3600) * 1000
      status.value = 'connected'

      // 写入 auth store 的内存状态 (不 persist)
      auth.setToken(accessToken, undefined)

      // 启动续签定时器
      startRenewTimer()
    }
  }

  const startRenewTimer = () => {
    if (timer) clearInterval(timer)
    timer = setInterval(() => {
      if (Date.now() > expiresAt - 10 * 60 * 1000) {
        status.value = 'expired'
        // 请求父页续签
        window.parent.postMessage({ type: 'RENEW' }, ALLOWED_PARENT_ORIGINS[0])
      }
    }, 60_000)
  }

  onMounted(() => {
    // 基础级: URL 已有 token → 跳过握手
    const urlToken = new URLSearchParams(location.search).get('access_token')
    if (urlToken) {
      status.value = 'basic'
      return
    }

    // 非 iframe 环境 → 正常用户, 不启动握手
    if (!isInIframe()) {
      status.value = 'idle'
      return
    }

    // 推荐级: 启动 postMessage 握手
    status.value = 'waiting'
    window.addEventListener('message', handleMessage)

    // 告诉父页: 我准备好了
    // 遍历白名单发 READY (父页只会响应匹配自己 origin 的那条)
    ALLOWED_PARENT_ORIGINS.forEach(origin => {
      window.parent.postMessage({ type: 'READY' }, origin)
    })
  })

  onUnmounted(() => {
    window.removeEventListener('message', handleMessage)
    if (timer) clearInterval(timer)
  })

  return { status }
}
```

**父页代码**（三方前端）：

```ts
const iframe = document.getElementById('benefit-embed') as HTMLIFrameElement
const BENEFIT_ORIGIN = 'https://benefit.example.com'

window.addEventListener('message', async (e) => {
  // ① Origin 校验
  if (e.origin !== BENEFIT_ORIGIN) return

  if (e.data?.type === 'READY' || e.data?.type === 'RENEW') {
    // ② 向自己后端拿短期 token
    const { access_token, expires_in } = await fetch('/api/embed/benefit-token', {
      method: 'POST',
      credentials: 'include',  // 带三方侧的 session
    }).then(r => r.json())

    // ③ 发给 iframe, 指定 targetOrigin
    iframe.contentWindow?.postMessage(
      { type: 'TOKEN', access_token, expires_in },
      BENEFIT_ORIGIN,  // ← 浏览器校验: iframe 的 origin 必须匹配
    )
  }
})
```

**为什么安全**（逐条分析）：

| 攻击向量 | URL 带 token | postMessage 握手 |
|---|---|---|
| 服务端 access log 泄漏 | ❌ token 在 URL, 必然记录 | ✅ URL 不含 token |
| Referer 泄漏 | ❌ 跨域请求带完整 URL | ✅ URL 不含 token |
| 浏览器历史 / 书签 | ❌ 永久保存 | ✅ 无 token 可存 |
| MITM 截获 HTTP | ⚠️ HTTP 时可截 | ✅ postMessage 走内核 IPC, 不走网络 |
| 恶意浏览器扩展 | ❌ 可读 URL / localStorage | ⚠️ 可读内存 (但无持久化) |
| 错误监控 (Sentry) | ❌ 默认采集 URL | ✅ URL 不含 token |
| 跨 origin 滥用 | ❌ 拿到 token 即可用 | ⚠️ token 不在 URL, 但仍可从内存读 |
| iframe 内 XSS | ❌ 读 localStorage | ⚠️ 读内存 (短期化缓解) |

**残余风险与缓解**：

| 残余风险 | 缓解 |
|---|---|
| iframe 内 XSS 读内存 token | CSP `script-src 'self'` + 禁 `v-html` + token TTL ≤ 1h |
| 恶意浏览器扩展注入 content script | 无法防（扩展有最高权限）；短期化降低窗口 |
| 父页 XSS → 攻击者控制 postMessage | 父页安全是三方自己的责任 |
| 父页把 token 写进自己 localStorage | 建议三方只存内存；这是三方的代码 |

### 8.3 两级通用的后端安全要求

无论第三方选哪级，后端**必须**做：

| 项 | 要求 | 说明 |
|---|---|---|
| **frame-ancestors** | `Content-Security-Policy: frame-ancestors <白名单>` | 禁 `*`；按签约三方域配置 |
| **CORS** | `Access-Control-Allow-Origin: <白名单>` | 禁 `*`；`Allow-Credentials: false` |
| **HTTPS** | 强制 TLS 1.2+ | HSTS header |
| **token TTL** | ≤ 1 小时 | 签发时 `expires_in` 上限 |
| **限流** | `/benefit/api/v1/**` 按 appId 限流 | 用 `fwk4j-rate-limit` |
| **state-change 不走 GET** | 所有修改操作必须 POST/PUT/DELETE | 防 CSRF via GET |

### 8.4 安全标准对照

| 标准 | 条款 | 基础级 | 推荐级 |
|---|---|---|---|
| **等保 2.0 (GB/T 22239)** 身份鉴别 8.1.4.1 | JWT + Refresh + 踢人 | ✅ | ✅ |
| **等保 2.0** 通信保密性 8.1.4.5 | HTTPS + token 不落盘 | ⚠️ 落 localStorage | ✅ 内存 |
| **等保 2.0** 剩余信息保护 8.1.4.9 | token 短期化 + 不写持久存储 | ⚠️ | ✅ |
| **等保 2.0** 安全审计 8.1.4.3 | 审计日志 Hash Chain | ❌ 需补 | ❌ 需补 |
| **ISO 27001** A.8.5 身份认证 | JWT + Refresh | ✅ | ✅ |
| **ISO 27001** A.8.12 数据防泄漏 | token 不暴露 | ⚠️ | ✅ |
| **NIST CSF** PR.AC 访问控制 | RBAC + appId 隔离 | ✅ | ✅ |
| **OWASP Top 10** A01 访问控制 | Origin 校验 + frame-ancestors | ⚠️ 需配 | ⚠️ 需配 |
| **OWASP** A02 加密失败 | HTTPS + 字段加密 | ⚠️ | ⚠️ |
| **OWASP** A07 认证失败 | JWT + 短期化 | ✅ | ✅ |

### 8.5 绑定策略（不做什么）

| 维度 | 决策 | 理由 |
|---|---|---|
| parent origin | ✅ 绑 | 浏览器强校验 Origin 头, 真有效 |
| path | ❌ 不绑 | 阻断合法 SPA 路由跳转 |
| UA | ❌ 不绑 | 完全公开可伪造, 绑了等于没绑 |
| IP | ❌ 不绑 | 移动网 / NAT / 代理跳 IP, 误杀率高 |
| TLS fingerprint (JA3) | ❌ 不绑 | 嵌入场景不需要, 复杂度高 |
| Device fingerprint | ❌ 不绑 | 误杀率高, 用户切换设备就 401 |

## 9. 未来扩展：micro-app 集成

当前方案（iframe + postMessage）是**嵌入场景的最优解**。如果未来需要与宿主
系统做**深度 UI 集成**（共享导航、共享状态、无感路由跳转），可考虑 micro-app
（微前端）方案。

### 9.1 什么时候该用 micro-app

| 场景 | iframe（当前） | micro-app |
|---|---|---|
| 三方前端嵌入管理后台 | ✅ 推荐 | ❌ 过度 |
| 同团队共享设计系统 / 路由 / 状态 | ⚠️ 割裂 | ✅ 推荐 |
| 需要无感跳转（宿主侧栏 → benefit 页面） | ⚠️ iframe 滚动条 | ✅ 推荐 |
| 需要共享登录态（同一 cookie / store） | ⚠️ 需 postMessage | ✅ 天然共享 |

### 9.2 框架选型

| 框架 | 隔离方式 | 与 benefit4j 适配 | 集成代价 |
|---|---|---|---|
| **wujie**（腾讯） | iframe 做 JS 沙箱 + Web Components 做 DOM | 最好 — 本质还是 iframe 隔离 | 中 |
| **qiankun**（蚂蚁） | single-spa + JS 沙箱（proxy） | 需改入口（导出 mount/unmount） | 中高 |
| **micro-app**（京东） | Web Components + proxy 沙箱 | 类似 qiankun | 中 |

**推荐 wujie**：底层仍是 iframe（JS 跑在 iframe 里），DOM 渲染到宿主页的
Web Components 里。对 benefit4j 的改动最小，安全模型与当前方案一致。

### 9.3 wujie 集成示例

```ts
// 三方侧
import WujieVue from 'wujie-vue3'
app.use(WujieVue)
```

```html
<!-- 三方模板 -->
<WujieVue
  name="benefit"
  url="https://benefit.example.com/benefit/tenant/page/dashboard?brand=acme&mode=dark"
  :props="{ accessToken: token }"
  :attrs="{ referrerpolicy: 'no-referrer' }"
  style="width:100%;height:780px"
/>
```

benefit4j 侧**几乎不用改**（wujie 自动处理生命周期）。token 传递从 postMessage
变成 wujie 的 `props`（wujie 内部走 iframe postMessage，安全模型不变）。

### 9.4 改造清单（仅在决定上 micro-app 时执行）

| 改动 | 说明 |
|---|---|
| benefit4j 入口导出 `bootstrap/mount/unmount` | qiankun / micro-app 需要；wujie 不需要 |
| 路由 `base` 动态化 | `createWebHistory(import.meta.env.BASE_URL)` 改为运行时注入 |
| `localStorage` key 加前缀 | 防与宿主冲突（如 `benefit4j:access_token` → `{appId}:benefit4j:access_token`） |
| element-plus popper 挂载点 | `el-dialog` / `el-popper` 默认挂 `document.body`，会逃逸沙箱；需改为挂到子应用容器 |
| 宿主侧安装同框架 | 三方需装 wujie-vue3 / qiankun，版本耦合 |

> **当前不执行**。iframe 方案已满足嵌入需求，micro-app 留给「同团队深度集成」场景。
