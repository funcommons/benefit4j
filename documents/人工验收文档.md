## 3. 启动流程(从零到可验收)

```bash
# ① 基础设施(PG + Redis 容器,已起可跳过)
docker start pg-17 redis

# ② 后端(Flyway 自动执行迁移,V1.3.x 建 assets 六表 + 种子;首次起 ~40s)
cd backend/benefit4j-app && mvn spring-boot:run
# 验证: curl -s http://localhost:9200/benefit/api/v1/ops/health

# ③ 前端(自动打开浏览器)
cd frontend && npm run dev        # 9203

# ④ 登录
#    浏览器 → http://localhost:9203/benefit/app/platform/login
#    输入 PLATFORM / fvUQ54yPgrMg2v2X → 进入平台工作台
```

API 直连验收可先换 token(后续 curl 通用):

```bash
TOKEN=$(curl -s -X POST http://localhost:9200/benefit/api/v1/auth/token \
  -d "grant_type=client_credentials&client_id=PLATFORM&client_secret=fvUQ54yPgrMg2v2X" \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['access_token'])")
echo $TOKEN   # 备用;Authorization: Bearer $TOKEN
```

### 4.3 平台 API(平台登录 token 直连)

> 通用:`curl -H "Authorization: Bearer $TOKEN" ...`;预期均 `"code":0`(HTTP 200)。
> 运营端点为 `/benefit/api/v1/platform/assets/**`(APP 型 token,平台登录可用);
> 运维通道 `/benefit/api/v1/assets/ops/**`(reconcile / idempotency-release / credit-limit)要求 OPS 型 token,
> 登录端点不发放,由运维签发 —— 人工验收走自动化(§4.4 F2/F3)。

| D2 | 新建资产 | `POST .../platform/assets` body `{"code":"ACPT2","name":"验收","asset_type":"VIRTUAL","precision":2}` | 返回该资产定义 | □ |
| D3 | 停启用 | `POST .../platform/assets/ACPT2/suspend` → `.../resume` | 均成功;重复停用幂等不报错 | □ |

### 4.4 资金链路(runtime,当前为签名全拒模式)

runtime 资金 API(`issue/pre-consume/settle/refund/freeze/unfreeze/exchange/repay`)要求 **APP token + HMAC 请求签名**。当前签名密钥表为空(InMemorySecretProvider 未注册密钥)= **全拒模式**,这是等接入方配置前的**安全默认**;因此资金链路的人工验收走「自动化回归」(§6 命令,含 148 IT + 4 smoke):

| # | 验收点 | 方式 | 预期 | 结果 |
|---|---|---|---|---|
| F1 | 签名全拒生效 | `POST /benefit/api/v1/assets/runtime/issue`(带平台 token、无签名头) | 拒绝(非 200,`"success":false`) | □ |
| F2 | TCC 全链正确性 | `mvn -pl benefit4j-it test -Dtest='Assets*IT'`(§6) | 全绿:issue→pre-consume→settle/refund、双扣、冻结、兑换、授信还款、幂等重放;运维通道(reconcile/幂等释放/授信调额)同覆盖 | □ |
| F3 | smoke 真实进程 | 起 app 后跑 `AssetsSmokeIT`(§6) | 4/4 绿:平台正例链(APP token)+ 运维通道(OPS token)+ 签名拦截 + 无 token 401 | □ |

> 接入方注册签名密钥后,可按 [assets-design §9.3] 的六步端到端剧本人工走资金链(本文档不重复)。

## 5. 排障速查

| 现象 | 原因 | 处置 |
|---|---|---|
| 登录 401 / 认证失败 | secret 错;或 Redis 未起 | 核对 §2 账密;`docker start redis` |
| 运维通道 401「令牌类型不匹配」 | 登录端点只发 APP 型 token,`assets/ops/**` 要求 OPS 型 | 预期行为(型别隔离,§4.5 S5);运维操作走 OPS token(运维签发)或自动化 |
| runtime 资金 API 全被拒 | 签名密钥未注册(全拒模式) | 预期行为,见 §4.4;接入方配钥后放行 |
| 前端页 404 | 直刷 `/benefit/platform/app/*` 被 dev server 吞 | 从登录页进入;生产 Nginx 已配 SPA fallback |
| 后端起不来 `fiat-allowed` 断言 | 库里被手工插入 FIAT 资产 | `DELETE FROM ubmx_asset WHERE asset_type='FIAT'` 后重启 |
| smoke 被 skip | app 未在 9200 运行 | 先 `mvn spring-boot:run`,日志见 `Started Benefit4jAppApplication` 再跑 |
| 新端点 500/404(代码已改) | app 用本地仓库旧 starter jar | `mvn -pl benefit4j-starter install -DskipTests` 后重启 app |
