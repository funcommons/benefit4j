# benefit4j 权益模板样例集

> **版本** v1.2.6 · **更新** 2026-08-22 · **状态** 已发布 · **维护** benefit4j 团队
> 以代码现状为准。

## 1. 概述

本文档沉淀一套跨场景、跨行业的"权益项 + 权益集模板"样例数据，覆盖国内外知名 APP 的核心会员体系。供平台运营/前端开发/产品设计参考、对照真实业务。

> **字段约定**（与 `backend/schema.sql` 的 `ubmp_benefit_tmpl_item/set/ref` 表结构对齐）：
>
> - 权益项（`ubmp_benefit_tmpl_item`）：`name`、`icon`、`description`、`default_deduction`、`status`
> - 权益集（`ubmp_benefit_tmpl_set`）：`name`、`duration` + `duration_unit`、`quota`、`priority`、`refresh_cycle` + `refresh_cycle_unit`、`status`、`refs`（关联权益项，含 `quota` / `refresh_cycle` / `refresh_cycle_unit`）
> - `duration_unit` / `refresh_cycle_unit` ∈ `day | week | month | year`

| item-private-model | 0 | 0 | month |

> **额度约定**：`item-coding-token` 的 `quota` 数值统一按"输入+输出合计 token"计（如 300000 ≈ 300K token）。前端按此 `category` 渲染"≈ N 次对话"提示。`item-coding-agent` 的 `quota` 是每月 Agent 步数上限。

## 3. 使用建议

1. **跨集复用权益项**：同一 item_id 可被多个 set 引用（例如 `item-priority-cs` 出现在京东 PLUS、滴滴、携程等），符合"原子化权益"设计理念。
2. **额度单位约定**：`quota` 字段是数字，"次/元/GB/KG"等单位放在描述里统一表达；具体行业单位由前端按 `category` 渲染。
3. **刷新周期**：用 `refresh_cycle` + `refresh_cycle_unit` 组合表达（如每月 1 号刷新、每年 1 月 1 日刷新）。`0 + month` 表示不刷新（永久累计）。
4. **优先级**：`priority` 数字越大，核销时越优先扣减（与后端 `ubma_benefit_set.priority` 语义一致）。
5. **状态**：本文档默认 `ACTIVE`；`INACTIVE` 用于已下架模板。
